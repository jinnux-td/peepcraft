# @kit/peeps-creator

How to use it, set the default colour of each item, and set up the pieces of an item: [docs/peeps-colours.md](../../docs/peeps-colours.md).

**Assembly:** a character creator for [`@kit/peeps`](../peeps) as one React component. Drop it in a page or in a dashboard panel; `@kit/peeps` itself stays free of any UI, so other packages can use `Peep` alone.

```tsx
import { PeepCreator } from '@kit/peeps-creator'

<PeepCreator
  defaultState={{ type: 'sitting', bg: 'transparent' }}   // anything left out is the default
  onChange={(state) => save(state)}                       // the whole state, after every change
  onExport={({ kind, name, blob }) => upload(name, blob)} // without it, Save downloads the file; name comes from the parts ("bust-afro-smile-tee-1.png")
  theme={theme} onThemeChange={setTheme}                  // or defaultTheme="noir" and let it keep the theme
  showThemeButton title="Avatar" className="my-panel"
  shareBase="https://peepcraft.jinnux.com/"              // optional: a Copy link button; the host opens #d=... links
/>
```

- **Parts:** a tab per category (type, body, hair, face, facial hair, accessories), each an option grid of small pictures on the current figure.
- **Extra:** a tab after Accessories for what the peep wears beside it, the `extras` of [`@kit/things`](../things) (speech, round and thought bubbles by the head; an aura around the peep, following its outline; more go in the same group with a `place`). One at a time, or None. Its dots, **Extra lines** and **Extra fill**, start in the extra's own colours (a bubble `#111111` on `#f2f2f2`, the aura gold `#f4b400` on pale yellow `#fff3bf`) and start over when an extra is chosen again. The aura is drawn behind the peep, its outline grown 150 units out (an SVG filter), so it fits every type and pose. The stage grows to hold it, and **Add** puts it in the scene with the peep, where its colours stay editable.
- **Figures:** a last tab with the 38 whole illustrations of [`@kit/transhumans`](../transhumans) (and a tile to go back to building a peep). A figure replaces the peep on the stage; colours, scale, rotate, flip, background and both exports work on it, parts do not apply, and the dice of the tab picks another figure.
- **Scene:** the last tab composes a picture of many: **Add** copies the current peep or figure into the scene, and the stage shows the scene while the tab is open. The left panel holds what can be added; the right panel lists the members, as tall as the window allows, then scrolling. Drag a member on the stage to move it across or up and down (one undo step per drag), or pick it (its tile, or a click on the stage) to set its position, size and lift (height above the ground, from -20 % to 80 %: a mug on a table is 25 %), flip it (`F`), send it back or to the front (or drag its tile to another place in the list), or remove it. Everyone stands on one ground line (the feet come from the measured outline), on the scene's background. Each member keeps its own colours, editable when picked: Lines, Fill, and the named parts of a thing (the leaves and the pot of a plant, the cushions of a sofa), one palette for the colour chosen; a small handle at each corner of the picked member resizes it, keeping the opposite corner where it is. Under the stage, **Ratio** (1:1, 4:3, 3:2, 16:9, 3:4, 9:16; members keep their place across the width) and **Zoom** (0.5 to 2, about the ground line) set the picture; the PNG follows the ratio (long side 1024 px). Save exports the whole scene, named after its members in drawing order (`scene_figure-runner_bust-bun-2-smile-tee-1.png`). **Things** adds one of the 22 drawings of [`@kit/things`](../things) in the current colours. **Uploads** takes a PNG, JPEG, WebP, GIF or SVG (5 MB at most) and keeps it in this browser (IndexedDB `kit-peeps-creator`), never on a server: it stays after a reload until its × is pressed, which also takes it out of the scene, or until the site's data is cleared. An upload is drawn as an `<image>` with a data URL, so an SVG's scripts never run and the exports carry the picture. Undo covers add, remove, flip and order. The scene is `state.scene`, so `defaultState` and `onChange` carry it. It is drawn with the `Scene` of `@kit/peeps`.
- **Dice:** one per tab changes that tab only (never to the same choice twice); **Shuffle all** rolls the type, then every part of that type, the extra (or none), the skin, lines and fill, leaving what is locked. A transparent background is left alone by Shuffle.
- **Colours:** a peep starts with skin `#d08b5b`, and every item comes in its own colours, which it carries (`atom.pieces`: its layer groups in the Open Peeps Figma file, the standing and sitting poses in the colours they came in before), so its thumbnail shows what you get. A tab shows a dot per piece of its item (Top, Pants, Shoes, Bandana, Mask, ...) and the item's Line; a colour picked for a piece stays until another item is chosen in that tab. See [docs/peeps-colours.md](../../docs/peeps-colours.md).
- **Thumbnails:** each item by itself, so choices are easy to tell apart; **On peep** in a part tab's header shows them on the whole peep instead (off on every load). The button beside it shows the items as a grid or a list (picture and full name a row); hovering an item shows its name. In Contrast the pictures sit on light grey `#f2f2f2` whatever the background. A tab opens at the top of its items; after a dice the grid (not the page) scrolls to the new choice.
- **Locks:** a padlock beside each tab's dice (a part, the type, the extra) and on Background keeps it when **Shuffle all** is pressed (`state.locked`); the dice of a tab still changes it. The type, the lines, the mask and the extra start locked, so a shuffle keeps the type and the lines and adds no mask or extra until they are unlocked. Skin, Lines and Fill have a padlock beside their swatches, and a small padlock on the dot once locked.
- **Contrast:** a button under Background draws everything in Lines and Fill only (black on white, as the pack does): no item colours, no skin, no picks; thumbnails, exports and scene copies follow, the tabs show no colour dots, and turning it off brings the colours back (`state.mono`).
- **Sliders:** a dot on the track marks the default (Scale 1, Rotate 0°, Zoom 1×, ...), and a drag that comes within 5 % of it (a step and a half at least) lands on it, so it is easy to go back to and takes a little more pull to leave.
- **Look:** background (a colour, or **transparent**); a click on a part of the peep on the stage opens its tab; scale, rotate, flip (also the `F` key), undo / redo / reset.
- **Numbers:** every slider has its value as a box to type in (kept in range) and a reset icon back to the default (scale 1, rotate 0°, position 50 %, size 1, lift 0 %, zoom 1×).
- **Share:** with `shareBase`, **Copy link** puts a link to the picture on the clipboard: the document of [`@kit/peeps-engine`](../peeps-engine) in the fragment (`#d=...`, deflated, so it never reaches a server). Under Save in the builder; an icon beside the PNG size in the scene, where the panel has no room for a row. A screen reader hears "Link copied" (a hidden status); a note shows only when uploads were left out (they stay in this browser) or the picture is too big for a link, and the link itself shows to copy by hand when the clipboard refuses. The host reads the link back: `resolve(await decodeShare(location.hash))` as `defaultState` (see `examples/peeps/main.tsx`).
- **Export:** SVG, and PNG at 1×, 2×, 3× or 4× (1024 px on the long side at 1×; the size is shown before saving). Transparent stays transparent in both (no rectangle in the SVG, alpha in the PNG).
- **Themes:** `sunny`, `glass`, `noir`, `violet` are the brand themes of `@kit/tokens`, set as `data-brand` on the component's root, so a host page is never restyled (noir and violet are dark). `data-pc-theme` is still set as an alias for one release. The stylesheet ships inside the component; the buttons, the sliders and the theme menu are `@kit/ui`.
- **Size:** the layout follows the width of the component (container queries), not the window: three columns when wide, stacked in a narrow panel or on a phone.

## Folders
The state and the picture (choosing, history, dice, scenes, the SVG exports, the window on each look) are in [`@kit/peeps-engine`](../peeps-engine), so the CLI and the MCP server draw what the creator draws. The stage no longer measures the outline in the DOM: the window on each type, figure and extra comes from the engine's table, measured once in Chromium (`npm run measure:peeps`).
```
src/colors.ts, png.ts, uploads.ts, types.ts             plain TypeScript: the colour chips, PNG in the browser, uploads in IndexedDB, tabs and themes
src/styles.ts                                            the stylesheet and the four themes
src/components/                                          PeepCreator (the whole), PartPicker, SceneSources and SceneMembers, Thumb, Stage, Swatches, Slider, ThemeMenu, icons
```
Each piece is exported, so a dashboard can use the whole creator or only, say, `PartPicker` with its own state.

Depends on `@kit/peeps`, `@kit/transhumans` and `@kit/things`; peer dependencies `react` and `react-dom` (>= 18). Node >= 22.23.4 for the tests; the components are `.tsx` and need a bundler (esbuild, Vite). `npm test` and `npm run typecheck` run inside the copy (copy `peeps`, `transhumans` and `things` with it). The browser test is `examples/peeps/e2e.test.ts`.
